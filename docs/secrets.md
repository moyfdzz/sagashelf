# Secrets: inventory and how to rotate each one

Names only. No value of any secret is written here, in the repository, in an issue or in a chat. This page is part 3 of SAG-29; the [incident plan](incident-plan.md) (what to do first when something leaks, how to close sign-ups and pause webhooks) is part 4 and uses this page.

Last checked against the code on 2026-11-04. The source of the list is `server/env.ts`, the only place where the variables are validated. If a variable is added there, add its row here in the same pull request.

Other things that are secret and are **not** variables of this Worker:

- **The address of each Discord webhook** that a person saves. It belongs to them, it is kept in plain text (ADR-029) and it is masked in the page, the export and every message. The owner cannot rotate it: the person deletes the webhook in Discord. The app turns an endpoint off by itself when Discord answers 401 or 404, or after 5 failures in a row.
- **The Google OAuth client secret** of the sign-in with Google. It was created in Google Cloud and pasted into Clerk's Google connection, so it lives in Clerk and in Google Cloud and never in this Worker.
- **`.dev.vars` on the owner's computer.** It holds real values, and its `DATABASE_URL` can point to a **remote** database. It is ignored by git. If the computer is lost or shared, rotate `DATABASE_URL` and the Clerk and TMDB keys.
- **`GITHUB_TOKEN` of the workflows** is made by GitHub for each run, has read permission (`contents: read`, plus `security-events: write` for CodeQL only) and nothing to rotate. Until SAG-135 the repository had **no** Actions secrets and no Actions variables (checked 2026-11-04). The daily backup (`.github/workflows/backup.yml`, [backups](backups.md)) adds six Actions secrets: `BACKUP_DATABASE_URL` (the direct address of a **read-only** role), `BACKUP_GPG_PUBLIC_KEY` (public, not secret in itself), `BACKUP_R2_ACCOUNT_ID`, `BACKUP_R2_BUCKET`, `BACKUP_R2_ACCESS_KEY_ID` and `BACKUP_R2_SECRET_ACCESS_KEY`. To rotate: reset the password of `backup_reader` in Neon, or make a new R2 token, and replace the secret in GitHub. The private key of the copies is **not** in GitHub and not in this repository: it is in the owner's password manager.

The accounts that give access to all of the above are the real keys of the project: GitHub, Cloudflare (also the registrar of the domain), Neon, Clerk, Google Cloud and Linear. 2-step verification on each one is item M-4 of the [security review](reviews/2026-11-security-review.md). The administrator of the app also needs 2-step verification on their Google account (decided 2026-10-31).

## How to rotate

Rotate when a value was exposed or might have been (it appeared in a log, a chat, a screenshot or a commit; a computer was lost; somebody who had access left). There is no schedule: a personal project with provider-managed keys gains little from rotating on a date, and each rotation has a moment when the site can fail. Look at this page once a year.

**The same three steps for every secret:**

1. Make the new value in the provider's dashboard, as the provider's page says. The old value stops working there, or soon after.
2. Put the new value in the Worker, from the repository folder, in **your own PowerShell** (the command asks for the value; paste it and press Enter, and it is not shown): `npx.cmd wrangler secret put NAME`. If it asks you to sign in, follow the browser window. For the previews, the same value goes in the **Previews Base** tab of the Worker's variables.
3. Check the thing that uses it (the last column below). Then remove the old value from wherever else it was (your `.dev.vars`).

| Secret                         | Make the new one in                                                                                                                                                       | Check afterwards                                                                               | What happens in between                                                                                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                 | Neon: reset the password of the role (the **pooled** string goes in the Worker, the **direct** one only in your terminal for a migration: see `.env.example` and ADR-002) | Open `/library` signed in, and look at the Workers log of the next hourly run for `job.failed` | Between the reset and step 2 every page that needs the database fails. Do both one right after the other.     |
| `CLERK_SECRET_KEY`             | Clerk, API keys, Production instance                                                                                                                                      | Change nothing in Ajustes; open `/settings/profile` and `/admin/sagas` (administrator)         | Deleting an account, changing a username and the admin guard fail until step 2. Sessions keep working.        |
| `CLERK_WEBHOOK_SIGNING_SECRET` | Clerk, Webhooks, the endpoint, its signing secret                                                                                                                         | Clerk's delivery log: send the example event and expect `200`                                  | New events answer 401 until step 2. Failed deliveries can be sent again from Clerk's delivery log.            |
| `TMDB_READ_ACCESS_TOKEN`       | themoviedb.org, Settings, API                                                                                                                                             | Search a title that is not saved and open it                                                   | The search answers from the database only until step 2.                                                       |
| `TURNSTILE_SECRET_KEY`         | Cloudflare, Turnstile                                                                                                                                                     | Nothing reads it; or delete it (SAG-132)                                                       | Nothing.                                                                                                      |
| `CLERK_JWT_KEY`                | Only if Clerk's keys are rotated: the new public key from Clerk                                                                                                           | Sign in and open `/library`                                                                    | Written in `wrangler.jsonc`, so it needs a pull request and a deployment: signed-in requests fail until then. |

The menu names of each provider change. If one differs from what is written here, look for the setting by its name and, if unsure, ask before pressing the button that revokes the old value.

## How a leak would be found

- **gitleaks** on every pull request (`Secrets (gitleaks)`), with the default rules and one exception: the exact value of each Clerk publishable key. Run over the **whole history** (181 commits, all branches, the repository's own config) on 2026-11-04 with the Docker image of the same version as CI (8.24.3): no leaks.
- **GitHub secret scanning:** 0 open alerts on 2026-11-04.
- **The environment check** names a variable that is wrong and never prints its value (`server/env.ts`).
- **Logs:** no log line carries a secret. An error that nobody handled is written by `handleError` (`server/http/error-log.ts`) without its message, so a failed database statement does not log the values it was sent (SAG-134), and a test fails for a `console` call that is given an error.
