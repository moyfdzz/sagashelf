# Security review, November 2026 (SAG-29, part 1)

Status: first part. The threat model of [ADR-006](../adr/006-security-model.md) was checked against the code, and the OWASP ASVS level 2 chapters were walked one by one. Each gap is a **finding** with a severity and ends as a ticket. Nothing here changes behavior.

## How it was made, and what it did not cover

Measured on `main` at `6fdd92e` (2026-11-04), by reading the code and the configuration, and by running searches over `app/`, `server/`, `workers/` and `db/` (`dangerouslySetInnerHTML`, `eval`, `sql.raw`, `z.object` against `z.strictObject`, `redirect(`, `Access-Control`, every `console.*` call), `npm audit`, and the file `wrangler.jsonc`.

**Not covered here, and where it goes:**

- It is a walk by **chapter** of ASVS 4.0.3, not a check of each of its requirements one by one, and it is not a penetration test. Nothing was attacked, in production or anywhere else.
- The authorization of the **reads** (anonymous, user, other user, friend, administrator) is part 2 of SAG-29. The writes are covered since SAG-128 (`app/routes/write-actions.test.ts`).
- What the logs print, the inventory of secrets and the rotation plan are part 3. The incident plan is part 4.
- What only the owner can do: the restore of Neon on a branch, the scripted burst against `sagashelf.app`, and a check of the Clerk protections in the **Production** instance (the settings in [edge-setup](../edge-setup.md) were written for the Development one). They are listed at the end.
- Clerk and Cloudflare are trusted for what they do (credentials, sessions, the edge). Only how this code uses them was read.

## The threat model against the code

The "Today" column of ADR-006 was out of date: it still said "Planned" for controls that exist. It is now updated. What changed, with the evidence:

| Threat                       | Was     | Is      | Evidence                                                                                                                                                                                                             |
| ---------------------------- | ------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bad input                    | Partial | Built   | 31 forms use `z.strictObject`; the few `z.object` strip unknown keys (the import file, the language form).                                                                                                           |
| Cross-site request forgery   | Partial | Built   | `checkWrite` in every write route, kept by a rule of `app/architecture.test.ts` and proven by `write-actions.test.ts`. One exception: finding S-1.                                                                   |
| Account takeover             | Planned | Built   | Clerk holds the credentials. The deletion of an account asks for a recent sign-in, and the administrator needs a verified Google login (`server/auth/require.ts`). The Production settings need the owner (M-3).     |
| Bots, scraping, abuse        | Partial | Built   | Bot Fight Mode, AI bot policy, the `API Burst` rule, `robots.txt` and the limiters ([edge-setup](../edge-setup.md), checked 2026-10-21). Turnstile is the one of Clerk's sign-up, not ours (S-3).                    |
| Broken access control (IDOR) | Planned | Built   | The id in a query is the one of the session; `canView` is the single policy with no user enumeration. The write routes are tested (SAG-128); the reads are part 2.                                                   |
| SSRF                         | Partial | Built   | The only address a person gives is a Discord webhook, parsed against an allow list, `redirect: "manual"`. The image proxy fetches allowed provider hosts and follows a redirect only to the hosts of its list.       |

| Webhook forgery (incoming)   | Planned | Built   | Svix signature (a request with a 10 minute old timestamp is refused) and idempotency by event id (`webhooks.clerk.ts`; run against the Worker on 2026-10-22, see edge-setup).                                        |
| Webhook abuse (outgoing)     | Planned | Built   | Discord only: allow list, masked address, no redirect, an endpoint is turned off after 5 failures in a row (`server/webhooks/outcome.ts`). The generic signed webhooks of the old plan were never built (ADR-029).   |
| Spam and harassment          | Partial | Partial | Blocks, mutes and the three profile levels exist. Reports and moderation are SAG-22.                                                                                                                                 |
| Cost abuse of providers      | Planned | Built   | A rate limit and a circuit breaker per provider (`server/providers/http.ts`), caches, local-first search, a query limit of 100 characters. One hole: S-1.                                                            |
| Personal data in logs        | Planned | Built   | Every `console.*` call prints an event name and the **name** of an error, never a message, an address or an email. Part 3 checks the places that log a whole error.                                                  |
| Data loss                    | Planned | Planned | Neon point-in-time restore, not tried yet (M-1).                                                                                                                                                                     |

| -------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| V1 Architecture            | Met                    | Threat model (ADR-006), design rules and a test that keeps them (ADR-033), a thin route, one policy for who can see whom (ADR-031).                                                                                                                                    |
| V2 Authentication          | Delegated, one check   | Clerk: breached-password check, verification, bot challenge. Deleting an account asks for `reverification: "strict"`. The administrator needs a verified Google login. M-3: confirm the Production instance.                                                           |
| V3 Session management      | Delegated              | Clerk's cookies. Our own cookie (`locale`) is `HttpOnly`, `SameSite=Lax` and `Secure` in production. Signing out clears the session cookies (`clear-session-cookies.ts`). "No account" and "wrong role" get the same 403, so a refusal does not say which one failed.  |
| V4 Access control          | Met for writes         | Every write: size, `Origin`, session, limit, in a pinned order. Reads: part 2.                                                                                                                                                                                         |
| V5 Validation and encoding | Met                    | Zod at every boundary, parameterized queries, React escaping, no `dangerouslySetInnerHTML`, no `innerHTML`, no `eval`, a CSP with a nonce per page and no inline style.                                                                                                |

The Discord webhook address is kept in plain text, a decision written in ADR-029 (masked everywhere it leaves the server). ## Findings

| Id  | Severity | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Ticket  |
| --- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- |
| S-1 | Medium   | **`/media/open` is a `GET` that writes, and anyone can call it.** A title that is not saved yet is fetched from a provider and stored. It needs no session and no `Origin` (a `GET` has none), and its only limit is the search limiter (60 a minute per IP address and per Cloudflare location). The `API Burst` rule covers `/api/*` only, and the Free plan allows one rate rule. Anyone can fill the database with titles, or spend the provider quota, with a loop over external ids; another site can also make a visitor's browser do it. | SAG-130 |
| S-2 | Low      | **The production audit of CI never fails.** `npm audit --omit=dev \|\| true` reports and goes on, so a vulnerable production dependency would not stop a merge (today there are 0).                                                                                                                                                                                                                                                                                                                                                              | SAG-131 |
| S-3 | Low      | **`server/turnstile.ts` is not used by any route**, only by its own test. Turnstile reaches users through Clerk's sign-up. The file reads as a protection that does not exist.                                                                                                                                                                                                                                                                                                                                                                   | SAG-132 |
| S-4 | Low      | **Nothing forces a new column that points to a person into the erasure and the export.** The rule is in `CLAUDE.md` and the list is in `server/db/erase-user.ts`, but no test reads the schema. `reports.reporter_id`, `reports.resolved_by` and `audit_log.actor_id` are left on purpose (the row stays), and the free text of a report will be personal data when SAG-22 exists.                                                                                                                                                               | SAG-133 |
| S-5 | Low      | **`workers_dev` is on and every preview is public.** It was already an open question in ADR-006. A preview has no production keys, but it answers like the site. Turning `workers_dev` off is a decision for the owner.                                                                                                                                                                                                                                                                                                                          | none    |

Accepted, with the reason:

- **24 vulnerabilities in `npm audit`, 9 of them high, all in development tools** (`@lhci/cli` and what it pulls in: Lighthouse, Puppeteer, `proxy-agent`, `body-parser`, `basic-ftp`). `npm audit --omit=dev` finds 0. None of it is in the Worker or is run on user input. The Dependabot alert about `minimatch` stays open on purpose. The ones that matter are the ones in production, which S-2 makes a rule.
- **The rate limit is approximate**: it counts per Cloudflare location and is eventually consistent (ADR-011). It slows abuse down and is not a quota.
