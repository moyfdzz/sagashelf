# ADR-011: Domain and edge security

- **Status:** Accepted
- **Date:** 2026-10-20
- **Implementation:** Done (SAG-7, 2026-10-21). The code, the custom domain and the Cloudflare dashboard settings are in place; the settings are listed in [`../edge-setup.md`](../edge-setup.md).
- **Tickets:** SAG-7, SAG-10, SAG-15

## Context

The domain `sagashelf.app` was bought at Cloudflare. The `.app` extension is on the browsers' HSTS preload list, so every visit must use HTTPS, which Cloudflare provides. The site is public, will have accounts and write endpoints, and runs on the Workers Free plan. Until now the only address was the `workers.dev` one, with no security headers, no rate limits and no policy for crawlers.

## Decision

### Security headers, in three places

Cloudflare's documentation (read 2026-10-20) says `_headers` files are **not applied to responses generated by Worker code**. So the headers come from three places that cover every kind of response:

1. **The Worker wrapper** (`workers/app.ts`) adds the base headers to every response the Worker produces, including JSON, redirects and error pages. Responses that are not pages also get `default-src 'none'; frame-ancestors 'none'`.
2. **The page renderer** (`app/entry.server.tsx`) creates a new nonce for every HTML page and sets the Content Security Policy that carries it. React Router applies the same nonce to its own scripts, links and inline scripts.
3. **`public/_headers`** gives static files (scripts, styles, `favicon.ico`, `robots.txt`) the same base headers. A unit test fails if this file and the Worker's list ever differ.

The base headers are `Strict-Transport-Security` (two years, subdomains included), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, a restrictive `Permissions-Policy`, `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Resource-Policy: same-origin`.

### The CSP

`default-src 'self'`, `script-src 'self' 'nonce-...'`, `style-src 'self'`, no `unsafe-inline` or `unsafe-eval`, `frame-ancestors 'none'`, `frame-src 'none'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`, and no other origin. It is sent by the **production build only**, because the dev server's hot reload injects scripts it cannot sign. An end-to-end test on the production build loads the page, hydrates it, switches language and fails on any CSP violation.

A feature that needs another origin adds exactly that origin to the one directive that needs it, in the ticket that introduces it. For example Turnstile needs `https://challenges.cloudflare.com` in `script-src` and `frame-src` (Cloudflare's documentation), and Clerk adds its own in SAG-10. The image proxy of SAG-17 needed none, because it serves the images from our own origin.

### HSTS without preload

HSTS is sent with `includeSubDomains` but without the `preload` directive. Submitting to the preload list is hard to undo, and the `.app` extension already forces HTTPS in browsers.

### Domain

- `sagashelf.app` and `www.sagashelf.app` become custom domains of the Worker, declared in `wrangler.jsonc`. Cloudflare then creates the DNS records and certificates. Custom domains match the exact host, so `www` is its own custom domain, and the Worker answers it with a `301` to the apex domain.
- The `workers.dev` address stays enabled during the move and is switched off in a later change once the custom domain is confirmed. Preview URLs are not affected.
- SSL mode is Full (strict) and DNSSEC is on (dashboard steps).

### Rate limiting, in layers

1. **A Workers Rate Limiting binding** (`WRITE_LIMITER`, 30 requests per minute per caller and per Cloudflare location) protects write endpoints. It is applied to `/api/locale` today, and later to follows and reports. Search has its own binding, `SEARCH_LIMITER` (60 requests per minute, namespaces 1002 and 2002), so reading does not use up the writes of the same caller (SAG-15). The image proxy has `IMAGE_LIMITER` (300 requests per minute, namespaces 1003 and 2003), which counts only the calls to the provider (SAG-17). A caller over the limit gets `429` with `Retry-After`. Worker Previews do not inherit bindings from the top level, so `wrangler.jsonc` declares the binding again inside `previews`, with a separate counter. Until accounts exist the caller is the IP address given by Cloudflare, and then it should be the user id.
2. **One WAF rate-limiting rule** at the zone level. The Free plan allows a single rule, with a 10 second window, the IP as the counting key, and only the path and the verified-bot flag as fields, so it covers `/api/*` as a whole.
3. **Bot Fight Mode**, which cannot be customized or bypassed on the Free plan.

A form handler rejects bodies over 4 KB with `413` before reading them, and an early answer reads and discards the small body so the local runtime can reuse the connection.

### Crawlers, including AI

- `robots.txt` (a static file) asks all crawlers to stay out of `/admin` and `/api/`, and asks the known AI training crawlers and agents to stay out of the whole site. Search engines are not blocked.
- In Cloudflare's AI bot policy (dashboard) **Training and Agent are set to Block and Search to Allow**. `robots.txt` is a request that well-behaved crawlers follow; Cloudflare's setting is what enforces it for verified bots.

### Turnstile

A server helper (`server/turnstile.ts`) verifies a token with Cloudflare's `siteverify` endpoint and returns false on any failure, expiry or repeat (a token works once and lasts five minutes). The widget is added to sign-up, sign-in after failures and public write forms when those pages exist (SAG-10). The secret key is a Workers secret named `TURNSTILE_SECRET_KEY`.

## Alternatives considered

- **Set the CSP in `_headers` or in a Cloudflare Transform Rule.** Neither can create a nonce per response, and `_headers` does not reach Worker responses. Rejected for pages.
- **Hash-based or `strict-dynamic` policies.** More moving parts than a nonce plus `'self'`, with no gain here.
- **A report-only CSP first.** Useful on a large existing site. Here the whole site is small and a test on the production build catches violations, so the policy is enforced from the start.
- **Submit `.app` to the HSTS preload list.** Not needed, hard to reverse.
- **Only dashboard rate limits.** The Free plan allows one rule, so the app-level binding covers the endpoints that need their own limits.

## Consequences

**Good**

- Every response, including errors and redirects, carries the security headers, and a test fails if the Worker and the static files disagree.
- Scripts without the page's nonce do not run, which removes the usual cross-site scripting payloads.
- The same code runs on previews and production, so headers and limits can be checked on a pull request before they reach the domain.

**Costs and risks**

- The CSP does not exist in development, so a CSP problem shows up only in the end-to-end tests on the production build and in CI.
- Every new third-party script, frame or API origin needs a deliberate CSP change.
- `Cross-Origin-Opener-Policy: same-origin` breaks sign-in flows that use a popup window. If the account provider needs a popup, relax it to `same-origin-allow-popups` in SAG-10 and record it.
- The rate limit counts per Cloudflare location and is eventually consistent, so it slows abuse down but is not an exact quota. The Free plan's single WAF rule is coarse.
- Switching to the custom domain changes DNS in production and, once `routes` is set, Wrangler turns `workers.dev` off by default unless `workers_dev` is set explicitly. The change sets it explicitly.

## Open questions

- **Resolved: the Free plan accepts and enforces the Workers Rate Limiting binding.** Checked on the pull request preview: 200 parallel requests from one caller produced 35 `429` answers, and a following sequence mixed `303` and `429`. The count is approximate (Cloudflare calls it permissive and eventually consistent): 45 requests sent one after another were not throttled at all. Treat 30 per minute as a soft target, not an exact quota.
- **Resolved: `public/_headers` is applied to static files** by the Vite plugin deployment. Checked on the preview: `favicon.ico` carries the base headers (in lower case, as Cloudflare's asset server writes them).
- **Decided: Search is left on Allow**, and Training and Agent are blocked, so the AI policy does not risk the search engines that matter for visibility.
- **Result on 2026-10-21:** Mozilla Observatory gives **A+** (score 145, 12 of 12 tests) and securityheaders.com gives **A+**. The only extra suggestion from securityheaders.com is `Cross-Origin-Embedder-Policy`, which is deliberately not set: it blocks cross-origin widgets (Turnstile, Clerk) unless every resource opts in.
- **Always Use HTTPS is on** (checked 2026-10-21: `http://` answers 301 to HTTPS). **DNSSEC is active** and its chain validates.
